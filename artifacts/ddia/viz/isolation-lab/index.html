Isolation Lab

Two or three transactions run against a small bank at the same time. Pick the isolation level and the replication topology, then step through the interleaving and watch what each transaction sees, what blocks, what aborts, and which anomaly survives.

Interleaving

This scenario across every level

Keyboard: ← → step, Space play or pause, Home reset, End run to the end.

What the engine models. Rows are multi-versioned: each version carries the transaction that wrote it. Read uncommitted returns the newest version regardless of commit state and takes no locks. Read committed returns the newest committed version and takes a row lock on write, held to commit. Snapshot isolation reads from the set of transactions committed at the transaction's start, and aborts a writer whose row was committed by someone else after that start (first committer wins). Serializable is snapshot isolation plus a record of every read, including searches; at commit, a transaction aborts if a concurrent transaction committed a write that would have changed one of its reads. A blocked step is deferred until the lock holder ends, then replayed.

What the topologies add. Single leader commits on the leader and applies each commit to the follower three steps later; transactions marked as read-only read the follower. Multi-leader runs each transaction on its own region's copy under the chosen isolation level, then reconciles the two copies by last commit wins. Leaderless has no transactions at all: every statement is an immediate quorum write or read, so there is nothing to isolate and nothing to abort; the isolation selector is disabled.
